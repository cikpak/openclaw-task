## The assessment's four optional bonuses

| Bonus                 | Coverage and boundary                                                                                                                                                                                                                                                                                                  |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Device Authentication | Implemented: persisted Ed25519 identity and device-authenticated connection through the official client, exact identity/role/scope pairing, bootstrap regressions and actual Gateway acceptance.                                                                                                                       |
| Tool Call Display     | Implemented for allowed read/write/edit/web-fetch tools: native agent tool events become named running/completed/failed chips. Hover/focus/click details show bounded, redacted parameters and output. Failure paths have application tests; actual write/read and reconnect have Gateway evidence.                    |
| Config Generator      | Partial: startup generates `openclaw.json`; native agent creation/deletion updates configuration programmatically. Agent Settings updates session settings and an app-managed instruction file. There is no general configuration-generation/editing API or UI; existing native configuration is preserved on restart. |
| Image Attachments     | Implemented within signature, ownership, capability and size limits: actual TXT/Markdown/text PDF/PNG consumption and native image downloads have Gateway evidence. Paid-provider interpretation and scanned PDF behavior remain separate.                                                                             |

Durable Queue/Steer and coordinated per-chat settings are additional application
features, not replacements for the assessment's named bonuses. Native artifacts
and ordinary generated workspace files use different scoped download paths;
writing a document does not make it a native transferable image artifact.

## Remaining limits to keep visible

Already-uploaded attachments may enter the offline queue only against capabilities last verified for the exact agent/session/model scope. Dispatch revalidates that scope before sending bytes. A restarted backend without that cache returns actionable `ATTACHMENT_CAPABILITIES_UNAVAILABLE`, retaining the browser draft and upload for retry. Confirmed deletion clears active/queued work and the owned Gateway workspace, but mutation receipts and recovery tombstones remain: this is not a complete backend-data erasure guarantee. Snapshot/history reads are not persisted as command receipts.

There is one backend coordinator and one account, with no distributed queue, registration, or roles. SQLite and Gateway state volumes must be backed up together. CPU/memory profiling under ten simultaneous external model runs is not part of deterministic acceptance. A scanned PDF can depend on the pinned extractor's image fallback and image-capable model; the acceptance PDF is text-bearing. Live-provider availability, paid-model behavior, external web-fetch output, and non-Chromium browsers require separately recorded checks.
