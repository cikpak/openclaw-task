# Private container helper

Docker build context is this directory. The image pins OpenClaw 2026.10.1. Only the authenticated helper starts at boot. Gateway uses private port 18789, without application TLS; helper uses private HTTP port 8787. Gateway runs as uid/gid 1000, helper as root to restore arbitrary original uid/gid/modes. No helper WebSocket, synthetic provider, fixture or seed endpoints exist.

Required private environment: `HELPER_TOKEN`, `GATEWAY_TOKEN` (32+ characters), `EXPECTED_MANAGER_DEVICE_ID`, `EXPECTED_MANAGER_PUBLIC_KEY`, `BOOT_ID`, `R2_ORIGIN` (HTTPS account S3 origin). `RESTORE_EXPECTED=1` forbids initialization and requires a complete verified restore before Gateway start. The manager must durably distinguish pristine initialization from every later boot, including a failure before the first checkpoint. `DEFAULT_MODEL` applies only at pristine initialization. Credentials are never returned by this API.

Every request needs `Authorization: Bearer <helper token>`. `GET /health` returns `{helperReady,gatewayState,bootId,restoreExpected,initialized,restored,initialRootEmpty}`. `POST /jobs` accepts `{operationId,bootId,action,data?}` and immediately returns a job. `GET /jobs/<id>` polls it. `POST /jobs/<id>/cancel` with `{bootId}` requests cancellation; poll until terminal status before restarting Gateway. Jobs include `bootId`, stable `operationId`, `action`, `status` (`running|succeeded|failed|cancelled`), timestamps, and a result only on success. Identical retries return the same job; reusing an ID for different data fails. One operation runs at a time. Stale boot requests fail. Cancelling an unknown ID records a boot-fenced tombstone so a delayed start cannot begin after cancellation. Terminal job IDs remain available for one hour; there is no fixed hourly job-count ceiling.

Actions:

- `initialize`: `{identity,config?}` on a proven pristine boot. Identity must match the manager public key/device ID provided at container creation and exact operator scopes. Defaults preserve native main agent mapping, concurrency 10 and existing tool policy. Explicit config may preserve additional agents/providers and settings. Configured absolute paths and known state/workspace path fields must remain below `/recovery`; existing symlink ancestors are audited before Gateway start, including rejection of workspaces redirected into excluded cache/tmp trees.
- `start`: start Gateway only after initialization/restore and config/trust audit. Manager separately verifies SDK readiness.
- `stop`: terminate Gateway process group gracefully, then verify all writers are gone, including detached engine-UID processes and other-UID writable descriptors into `/recovery`. Unverifiable process metadata fails closed; unrelated processes are never killed. Failure retains local data and refuses capture.
- `pair`: `{identity}` approves only the exact persisted expected manager's pending operator request/scopes. CLI output stays private and bounded.
- `full-message`: `{agentId,sessionKey,messageId}` reads an exact native current transcript through pinned read-only APIs, returns only visible user/assistant text, and omits reasoning/system/tool data. It requires the initialized running engine.
- `inspect`: stopped-engine inventory digest and SQLite validation.
- `capture`: `{checkpointId}` produces an immutable staged descriptor.
- `upload`: `{checkpointId,grants,reuse?: string[]}` uploads changed objects directly to R2; `reuse` may reference only content-addressed user objects already durably verified by the manager.
- `restore`: `{descriptor,grants}` downloads, verifies every object and tar member, reconstructs into a private staging tree, checks inventory/SQLite and only then installs into an empty recovery root. Failed verification leaves Gateway stopped.

Descriptor version 1: `{version,checkpointId,archive,manifest,files,inventoryDigest,counts}`. Each object has `{key,size,sha256,md5}` where MD5 is base64 for signed Content-MD5, SHA256 is whole-object hex. User file entries additionally have `{path,mode,uid,gid}`. Archive key is `recovery/<checkpointId>/internal.tar.gz`; manifest key is `recovery/<checkpointId>/manifest.json`; new user keys are `files/<generation>/<sha256>` (legacy `files/<sha256>` remain readable); reuse only exact matching keys from the trusted current committed descriptor supplied as capture `previousFiles`. Several paths may share one content-addressed object. Deduplicate grants by object key. Grants are `{key,url,headers?}` scoped to the exact HTTPS R2 origin, object and method by the manager's signer. Headers allow content-type/content-md5. Successful uploads return per-object size/hash/ETag receipts; ETags never replace checksums. Archive bytes never pass through the manager.

Meaningful HOME, state, config, identities, credentials and configured workspaces live under `/recovery`. Unknown regular files, directories and safe symlinks are preserved. Only controlled `cache`/`tmp` are rebuildable exclusions. All regular files below configured workspaces' documents directories become separate objects; separation does not grant browser publication. Private files elsewhere remain in the archive. Deletions follow exact generation inventory. Ownership/modes and safe symlinks survive; escaping links and special files fail closed. File content is preserved for hard links without promising inode identity. ACLs/xattrs and filesystem timestamps are outside the logical recovery contract.

Capture checks source stability, staging capacity and every SQLite-header database (including non-.sqlite names). SQLite opens only expendable private copies with WAL/SHM/journal sidecars, using the pinned Node runtime. Hashing, tar validation and transfers stream in bounded chunks. Authenticated metadata is capacity-bounded to one eighth of the pinned Node heap, independently of file bytes. Gateway restart cleans settled staging before starting writers. No experiment file-count or 128-MiB object limits apply. `/var/lib/messenger-helper` contains jobs/staging outside snapshots.

File requests remain authenticated on the separate private helper interface:

Optional file-audit `secrets` contain only credentials already available inside this container and the issued native device token. R2 account credentials and the manager private signing key remain inside the Durable Object and must never appear in helper request bodies.

- `POST /files/metadata` with `{agentId,sessionKey,path,secrets?}` returns only audited canonical path/documents root, safe basename/MIME, size/mtime and SHA256. The exact configured owner/session and an opened regular inode are required. Hidden/internal names, escaping symlinks and known credential content are private. Successful location checks alone do not publish; the manager requires explicit successful native write/edit evidence.
- `POST /files/input-metadata` with `{agentId,sessionKey,id,secrets?}` performs the same credential/inode audit for current handed-off inputs and returns SHA256, size/mtime, private canonical path, basename and MIME. The manager audits inputs before capture and grants asleep delivery only when this digest matches the committed object.
- `POST /files/read` with that scope streams current eligible bytes. `POST /files/input` with `{agentId,sessionKey,id,secrets?}` resolves a previously handed-off input manifest. Before headers, both pin the verified inode, stream into root-private immutable spool storage, scan known credentials across chunk boundaries and verify no concurrent modification. Later native writes cannot alter an admitted transfer. Cleanup follows stream completion/cancellation. HTTP admission deadlines must end once headers arrive; active bodies use manager-owned reader leases.
- `POST /files/handoff` with `{agentId,sessionKey,uploads:[{id,name,mimeType,size,sha256,key,url}]}` accepts at most five files, each 5 MiB and aggregate 10 MiB. Exact-origin signed GET grants for `staging/` objects are used without R2 credentials. Bytes are bounded and hash-verified before atomic placement under the configured workspace's `documents/.messenger-inputs/<session-hash>/<upload-id>/<name>`. A private preserved manifest makes retries stable and preserves native edits; missing current inputs fail closed. Handoffs require running Gateway, expose `filesBusy` in health, and prevent capture until settled. There is one 90-second batch deadline.

Native Gateway and pairing CLI subprocesses receive a filtered environment without helper credentials, boot/trust controls or R2 configuration. The helper runtime and compile cache are root-only; native compile cache is separate under excluded `/recovery/cache/native-compile`.
